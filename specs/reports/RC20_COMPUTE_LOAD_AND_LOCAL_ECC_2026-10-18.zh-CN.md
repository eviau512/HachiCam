# rc20：CPU/GPU 负载记录与局部配准返回契约

本轮先核对最新 rc19 证据、现有 CPU/GPU 实现及 SPEC_00/02/06，再修订权威规格，
最后实现采样、归档与局部优化器修正。GPU 占用率、调用耗时和实际采用次数分别记录，
不能互相替代。

## 最新手机证据

`hachicam_capture_20261018_111814_c7c6ab2d.zip` 稳定性与 CRC 通过；
SHA-256 `f977bf058c34eb1e9f73e680122c852d580b717a8ddc7cf94feb9827c66e9a64`。
最新组 `cce962ae-c031-4a72-9da7-e9aae8e541fb` 来自 rc19-1109。

拍摄到完整诊断快照 **28.295 s**：采集 4.157 s、解码 0.416 s、原生外层 23.520 s；
原生内部 23.505 s，其中全局 6.398 s、局部配准/验证 **13.322 s**。ZIP 导出约 0.135 s。
原生配准仍是主要等待；既有日志只有后端决策、调用/块数和调用耗时，没有 GPU 占用率。
实际采用 9 次全局 GPU 调用、29 迭代、192 个彩色块、4 个局部提案、5 张支持图和
3 个噪声网格；这些数字不能解释为 GPU 百分比。

来源为 4096×3072；成片 4014×2990，约 **12.002 MP**。四张 anchor 仅有 8/2961 个
合格重建块，面积比例 0.273% 低于原 2% 门槛，故保持 1x 输出；不是内存拒绝或关闭 SR。
本轮不放宽重建门槛或伪造 50 MP。实际基线约 33.333 ms /ISO 1351，未触发 rc19 的
高增益余量探测；不能以该组验证那项探测在高增益场景的效果。

## 新负载日志

测试版从拍摄、排队、原生处理到保存期间共享一个 500 ms 后台采样器。每组最多
600 条，紧凑 JSON 上限 128 KiB；单独保存为 `captures/<captureId>/compute-load.json`，
与参考帧、最终图和 manifest 一起原子归档。导出不重开采样，不增加旧 `capture/` 目录。

- 应用 CPU：进程 CPU 时间差/实际时间差，单核等效百分比可能超过 100%；另列稳定
  可用逻辑核数下的容量百分比。少于 100 ms 的启动间隔不伪造尖峰。
- 整机 CPU：`/proc/stat` 前八项差分，idle+iowait 不算忙，guest 不重复累计。
- 整机 GPU：Qualcomm KGSL 的原始 `gpubusy` busy/total 驱动窗口比率；保留原始对值、
  频率 Hz、读取时间/数据年龄、阶段和 Android 热状态等级。**包含相机、显示及其他应用**，
  不是本应用独占比例，更不是执行单元 occupancy。
- 无权限、无节点、分母为零、陈旧/畸形计数均为 `null` 并说明原因，绝不记作空闲 0%。
  只读固定节点；仅在已有测试版 root 探测成功时使用长驻 root helper，不逐样本申请 root。
- 成功/失败/取消均关闭会话，最后一个会话结束后异步停止 helper；有界生命周期/输出与
  陈旧隔离避免反复开进程。release 使用空实现，不启动采样或 root，不读节点、不保留轨迹。

计数语义依据 [Linux proc 文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html)
与 [KGSL 驱动实现](https://android.googlesource.com/kernel/msm/+/75057842e13cd89be1037d70db4cc84c65a3417e/drivers/gpu/msm/kgsl_pwrctrl.c)。
KGSL 是最近驱动窗口而非单调累计计数，因此不对相邻 busy/total 做差分，也不将频率当占用率。

## 本轮 GPU 修正与剩余负载

局部 CPU `COUNT|EPS` 达到 30 次上限后可返回有限的最终更新与末次相关性；旧 GPU 仅
发布 epsilon 收敛结果，其他有效上限结果可能被当成缺失并交 CPU 重算。本轮增加独立
返回状态与统计；迭代次数、几何/相关性/物理门槛保持。

新增上限类必须单独通过冷/热 CPU 数值比对，不通过则仅该类继续 CPU 补齐，不污染
原有收敛类。仍要求 0.05 来源像素/0.002 相关性，仍计真实筛选、上传、等待和 CPU
补齐成本，并保留 90% 成本门槛。实际 GPU 1/2 次迭代探针验证返回的是最终更新；
平坦、掩码不足、错误与完整 HDR/SR/回退检查继续执行。

仍值得优先迁移的工作，按后续顺序记录：

1. **局部物理验证**：高通/梯度变形、残差与掩码归约；与局部提案共享驻留平面，
   避免为每个候选反复传图。当前这一阶段和未采用提案的 CPU ECC 仍占局部时间。
2. **全局候选结构验证**：全图/区域变形、有效性和强度统计；现有 GPU 全局优化之后
   的候选评估仍留 CPU。跨曝光全局路径还需守住高光恢复负例，不能直接强开已有核。
3. **区域重建迭代**：采样/投影/累加适合分块常驻，先通过文本、白底噪声与内存验收；
   当前资格较少的场景未必是主要热点，不能以提高 GPU 占用为目的增加无用计算。

上述三项是待实施方向，本轮不声称全链 GPU 化。新采样将用来判断真实手机负载、频率/
热状态和阶段耗时；先用完整等待判断收益，不以桌面 GPU 或调用数代替手机速度验收。

## 验证与交付

两种模式各 **110** 项单测、standard Kotlin 和 debug/release 三 ABI 原生编译通过。实际 GPU 有界迭代结果、完整 HDR/SR/
降噪/视差/文档及九类回退或能力限制、全局数值拒绝与 CPU 结果复用通过。
后台 helper 固定协议及 stdin 停止已在宿主 shell 验证，停止约 47 ms；这不代替 Android
root 进程生命周期验收。手机节点可读性、采样开销/覆盖率及持续性能仍须新包实测。
