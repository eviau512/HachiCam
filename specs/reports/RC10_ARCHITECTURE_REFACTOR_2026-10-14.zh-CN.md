## 问题与规格

前置 [架构审查](ARCHITECTURE_AUDIT_2026-10-14.zh-CN.md) 确认：裁切会覆盖源图，
不同编辑路径使用共享结果文件且缺少请求修订检查；导出有缺页/失败处理缺口，
普通输入重建为约 50 MP 时没有统一资源估算，诊断与相机恢复也有身份/确认遗漏。
这些是代码与跨流程契约问题；尚不能把它们直接认定为实拍虚焦、噪点或高光失败的根因。

保留现有相机、检测与 JPEG 多帧合成，局部重构跨流程边界。先修订权威
SPEC_00/01/04/06 的完整编辑意图、代数、像素中心坐标、旋转/比例、文件提交、
读租约、导出清理与资源验收，再实现；随后同步 SPEC_03/05 的实现状态。
历史审查保留原始语境，不用报告代替权威规格。

## 已实现

| 边界 | rc10 行为 | 验收限度 |
| --- | --- | --- |
| 源图与编辑 | Crop / Review / Batch 共享 PageRenderer；master 不被旋转覆盖；裁切草稿取消不写源图；最终成片从 master 重算 | 原图是不可变私有路径身份，未增加持久化源哈希/缓存版本 |
| 意图与竞争 | Repository / RevisionLedger 按收到的顺序组合待处理滤镜、比例、旋转；进程递增代数；仅最新有效请求安装唯一成片并发布；失败保留上次提交 | OpenCV 阻塞操作可能继续执行，过期结果不提交；批量任务不是跨页原子事务 |
| 坐标与分配 | 持久化角点使用 0..width-1 像素中心；显示旋转与源坐标互逆；最终显示比例在 90°/270° 前逆变换；非有限/交叉/退化/越界几何及超过 56 MP 的输出拒绝 | 自由比例仍是实验估计，未增加纸张物理标定或缩小抗锯齿 |
| 拍摄提交 | 唯一 JPEG 安装与 READY 发布在同一 repository 锁内完成；处理中删除后不写回；READY 源图不被迟到回退替换 | 元数据仍在内存中，无进程死亡后的事务恢复 |
| 读与删除 | 渲染和导出取得读租约；被替换/删除的已提交文件等最后读者退出后再清理；会话结束不隐式删除保留源图 | 重启/存储清理 UI 与 durable metadata 未完成 |
| 导出 | 固定全部已提交页的起始快照；缺失/不能解码的页失败；MediaStore 项全部写完再发布；失败回滚本次创建项；零行删除需核对目标已不存在，无法确认清理单独报错 | 多 URI 发布不是系统级原子操作；权限/满盘等 Android 故障需实机注入 |
| 资源与 worker | 一个重型图像许可覆盖合成/保存、最终编辑/分析、导出、导入；排队 JPEG / 保留缓冲区计入估算；考虑 2× 输出与比例扩张；预算不足可降为原尺寸或流式合成 | 估算为实验参数，未测 RSS 上界；极端不足可失败，不能保证恢复 OOM/进程故障 |
| 过期分析 | 页面/草稿代数与取消检查保护边缘、结构线、轮廓结果；轮廓输入持有独立 Mat 引用并在完成/取消后释放 | 全部 UI 操作序列、弱边缘/吸附效果仍需实机验收 |
| JNI | 11 个图像入口转换 C++ / OpenCV 可恢复异常；检查数组、类型、几何、数值、曝光 tier/product 和搜索范围；Bitmap 解锁、Mat 和 CLAHE 缓存明确清理 | 不验证任意原生指针、不承诺拦截进程级故障；Android JNI 注入测试待补 |
| 诊断 | 最多 6 组有界拍摄记录；实际保留的最近完成组附自己的 diagnostics.txt；新拍摄实时日志明确另列 | 原始照片仍只保留最近完成一组，不能找回被下一组替换的输入 |
| 相机控制 | base/focus apply 与清理 clear/cancel 分别记录确认；清理失败阻止正常复用并请求会话重绑；处理 worker 接收前完成恢复记录 | 确认不等于硬件执行；仍需核对真实帧元数据并注入超时/失败 |

资源估算参数、降级顺序与限制见 SPEC_00；不把 Java heap 或任务数当作 native/RSS 测量。
原生高像素实验设置、条件 2× 重建、默认 Full HDR 与真实镜头切换保留。
本轮没有强制统一输出像素，没有调整配准/高光/重建质量门槛，也没有增加 RAW/GPU/OCR。
