原生阶段整机驱动 GPU 忙碌率采样均值约 17.0% /14.1% /17.5%；应用 CPU 约 507% /489% /477%（单核等效）。GPU 数据可能重复驱动窗口，包含显示、相机和其它应用，CPU 也涵盖整个进程；这些不是本次算法独占率。记录的 thermal severity 为 0，不能据此排除所有芯片级降频。

## 实现与保护

- 把原低信号、HDR 恒等捷径及细节能量不可能通过的检查提前，保持原判断。没有强预选提案的剩余节点可独立申请 GPU ECC；强预选阈值不再限制这个提案调度类别，最终物理验证和支持资格仍相同。
- 研究了每 patch 一个工作组的驻留路径：三次准备派发、一次完整迭代派发、一次发布，每块不等待其它工作组。原始帧回放表明部分弱纹理结果偏差超限、且成本偏高，因此最终发布路径直接使用既有分块归约，不在手机额外试探这个已知不利的方案。驻留核保留为宿主已测试的研究能力，不能把它算作手机新增卸载。
- 新的 base/highlight、图像尺寸与 batch 类别独立校准；保留 0.05 px /0.002 相关性容差、90% 成本规则、有限重试、原 30 次迭代及所有掩码/物理/噪声/细节门槛。高光类别不因其它类别通过而获得资格。
- GPU 缺少的提案仍由 CPU 完成。校准已得到的 CPU 成功结果、double 相关性和掩码/异常/变换失败码直接复用，避免再次计算；不把这些计入 GPU 提案数。新增诊断中的 `cpuTailCalls` 仅为校准之后的 CPU 尾部调用，物理重试另计 `gpuRetries`，校准的额外调用成本仍包含在完整等待中。
- 保留单 context、三缓冲和实际分配总计不超过 64 MiB。宿主驻留研究管线按需创建，发布路径不创建；release 与单 patch streaming 不启用新路径。没有实现灯罩轮廓恢复或全链 GPU 迁移。

## 验证状态

CPU、实际 GPU 的完整图像回归与九类故障检查通过。研究驻留 GPU 的 COUNT-bound 最终更新检查及 residual 批处理的平移/非方形/掩码/flat 检查通过；实际 residual 数值故障注入验证独立隔离、精确 CPU 结果及失败码复用，强提案和其它 GPU 阶段继续工作。

初步驻留单路径回放四组 CPU 成片逐字节一致，但新 GPU 类别全部被数值拦截，不能称为新增卸载或提速。加入分块归约备选后，首组开发机生产回放的剩余 base 类别通过，三帧分别实际发布 136 /170 /169 个 GPU 提案；高光类别仍被数值拦截。最终路径移除无益的驻留试探后，首组仍发布 475 /后续 491 个 GPU 提案；另两组未新增采用。宿主计时与 OpenCV 5 结果不替代 Ace3V /Android OpenCV 4.10 验收。

- 四组完整 CPU 成片与 rc24 逐字节一致。
- 完整自动后端首轮对照：近屏 /远屏一 /远屏二的最大通道差为 63 /52 /1，p99 为 1 /1 /0，平均绝对差约 0.0705 /0.0216 /0.0000015（0–255）。资格和其它后端路由也有差异，例如近屏 396→433 tiles；不是逐字节等价。近/远屏文字原尺寸局部目视未见新增明显重影，但这不是相机画质认证。
- 尝试把其它后端固定为 CPU，仅开放 residual 类别：四组均被真实数值校准拦截，GPU 提案为 0、图像逐字节相同。原本要求正例实际采用的断言未通过；这只能证明回退结果保留，**不能算独立 GPU 图像正例通过**。控制与失败记录保留在 `.tools/rc25-isolated.*`，该宿主控制不得包含在 Android 包内。自然图的固定后端 GPU 正例及手机验收仍未完成。
- 独立合成真值的实际 GPU、完整图像回归、数值隔离与九类故障检查通过；它们与上述未完成的自然图独立验收分别记录。
