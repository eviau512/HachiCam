# rc24：区域重建的 GPU 映射与求解

还没有证据表明 HachiCam 已达到无法优化的极限。本轮继续从已有样张定位热点、先修订 SPEC_02 §7.8/7.9，再实现并验证；没有要求用户补拍或再次授权才开始。

## 定位与改动

近灯冻结组的宿主 CPU 重放约 12.76 s，其中区域重建约 4.98 s。细分后的四线程累计时间中，观察映射约 13.79 s、迭代求解约 4.87 s；累计并行线程时间不是用户等待时间。这揭示了以往 global/local 大阶段之外的热点。

- 采样映射新增独立 Vulkan 内核：对有资格的基准帧，在最多 128×128 的源 ROI 内计算四个四分之一像素采样、三次逆局部迭代、细节/冲突/掩码与往返验证。矩阵先用 double 转成源 ROI/参考 patch 相对坐标，再转 float；避免在 4K 图像坐标上损失精度。
- 接近插值、位移冲突、掩码取整、patch 或往返阈值时仍由 double CPU 完成。冷/热结果需与完整 CPU 状态一致、坐标误差不超过 0.0005 源像素；数值不符隔离本类，保留 CPU 结果，不扩大 SR/HDR 资格。
- 迭代求解新增驻留内核：稳定 CSR 反向采样表按原次序聚合，避免浮点原子散射；每块一次派发完成八轮，保留原 16 taps、残差/修正上限和误差停止条件。对照 CPU 的最终像素最大误差上限 0.005。开发机完整成本仍偏向 CPU，不能把这个内核的存在说成实际卸载。
- CPU 也移除了重复工作：无局部场的三个零位移迭代直接省略，整个观察在首个无效四分之一采样处终止；向量有界预留，归一化只算一次，候选误差计算的残差供下一轮复用。顺序与数值保持不变。

两个 GPU 阶段分别计入整理/上传/执行/等待/读回和 CPU 补齐，用有效并行 CPU 成本及既有 90% 规则选择。共享三缓冲实际分配仍不超过 64 MiB；release 保持 CPU。streaming 尚未迁移，本轮也没有实现灯具最短帧的跨 bracket 配准或完整灯罩恢复。

同组日志增加 `regionalSolverVersion`、`regionalMappingVersion`，以及合并后的 GPU/CPU solver patch、GPU/CPU map job、CPU 歧义补齐数、重建 wall time 和工作线程累计映射/求解时间。映射时间可能包含 GPU 排队，不能当 CPU 独占时间；GPU 利用率仍是既有整机驱动窗口，不是应用独占率。

## 验证

- CPU 完整图像回归通过；四组冻结 CPU 最终图（近灯、远灯、PPT、暗底白字）与 rc23 逐字节一致。
- 实际 GPU 的 1027×769 /4096×3072 映射检查通过，涵盖相对坐标、透视、裁切源、掩码、缺失细节、冲突及图像边界；正例要求有足够有效观察且 CPU 补齐少于三分之一，避免用 CPU 完成冒充 GPU 通过。
- 实际 GPU 驻留 solver 与 CPU oracle、稳定 CSR、修正范围及常量/重复 tap/非法输入负例通过。现有 HDR/噪声/文字/区域重建/streaming、九类设备故障及全局校准回归通过。
- 实际生产校准的数值故障注入检查通过：solver 和 mapping 分别隔离、不反复试探，并逐位保留 CPU 校准数据；其它阶段继续运行。
- 固定所有其它阶段为 CPU，仅强制 GPU 映射的独立对照：近灯仅 319 个像素、PPT 仅 123 个像素变化，最大差 1、p99 为 0；远灯和暗屏不进入区域重建，结果逐字节相同。四组资格、尺寸和 CPU/HDR 基线不被强制放宽。宿主隔离测试不代表 Android 数值或相机画质验收。
- 完整自动路径另有既有全局/颜色/资格路由差异：PPT 首轮资格 109→107、全局 GPU 调用 9→6，成片有最多 50 级局部差异，不能全部归因于新映射。独立隔离上述新阶段后最大差仅 1；这些自动后端的边界差异仍需继续关注，不能用孤立优化的通过替代整体画质验收。
- 宿主测试用故障/映射隔离控制未包含在 Android 三种 ABI 包内；Android 构建和包内检查已通过，交付记录如下。

## 性能与剩余事项

同样的 O2/OpenMP 4/自动后端各重放四轮，首轮单列、后三轮中位。关闭研究图导出。原始记录保留在 `.tools/rc24-replays.json`，不把下表换算成手机速度或 30% 完整等待验收。

| 场景 | rc23 /rc24 首轮原生 | rc23 /rc24 后三轮中位 | 后续变化 |
| --- | --- | --- | --- |
| 近灯 | 13.809 /12.785 s | 11.068 /8.939 s | -19.23% |
| 远灯首次分组 | 9.101 /10.856 s | 6.311 /8.164 s | +29.37%，异常波动 |
| PPT | 12.146 /9.163 s | 6.841 /6.084 s | -11.06% |

远灯没有进入新重建路径，首次分组出现明显退步，不能跳过不报。两个进程交替运行、交替先后顺序的复测为：首轮 9.291 /9.205 s，后三轮中位 6.554 /6.380 s；未稳定复现首次退步，也不能据此声称远灯获得了明确优化收益。完整复测为 `.tools/rc24-interleaved.json`。

近灯首轮实际有 1510 个 GPU 映射 job、521 个 CPU job（包含参考图路径），182401 个候选经 CPU 歧义补齐；这些是 patch/plate job，不是帧数或 GPU 占用率。开发机迭代 solver 仍选择 CPU，新映射已实际采用；近灯变化主要伴随区域重建耗时下降，而不是仅增加内核数量。手机的 GPU 成本、首拍/连续等待和温度仍须新包同组日志确认。

近灯硬方块改善属于 rc23，本轮保留该处理。宽色块、灯罩轮廓及最短曝光被拒绝仍未达到 HDR-SEAM-22；不宣称 MotoCam 等效。手机新日志用于确认实际收益；有现成证据的批处理/驻留、跨曝光几何与响应工作继续，不以再次授权为前提。原始用户照片和中间图留在本机忽略目录，不上传仓库。
