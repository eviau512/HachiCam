# rc11 区域重建、对焦目标与验证记录

日期：2026-10-14；分支：`gpu-hdr`；版本：HachiCamTest 0.1.2-rc11-test。
本轮在现有基础上修改。工作顺序为问题分析 → 权威规格分析与修订 → 实现 → 验证。
算法参数仍属实验；没有宣称全部文字、夜景或设备控制已经验收。

## 1. 问题与证据

延续 [rc10 同组屏幕分析](RC10_SCREEN_ANALYSIS_2026-10-14.zh-CN.md)：132454 诊断包与
13:25 屏幕成片完全配对；源图 4096×3072，成片 4038×3014（12.17 MP）。实际拒绝
2× 的原因是整图平均局部支持 48.73% 未达 50%，而多处目标文字的区域支持明显较高。
降噪已经参与，整图资格与文字区域资格不一致。另一张墙面告示约 48.57 MP 为重建
输出，未证明原生 50 MP 捕获。131954 的缓存组不能误配该告示。

用户确认拍摄前点击了笔记本屏幕。旧快门逻辑超过 3 秒改用中心点，是控制策略缺口；
该组未记录点击年龄，不能认定本张虚感就是点击过期造成。焦距保持也不证明最初目标
达到最佳光学清晰度。

检查和独立图表还发现两项实现问题：原紧凑点核在新资格下的误差高于等尺度插值；
单独限制源图 ≤16 MP 不能保证 2× 输出 ≤56 MP。不能只放宽门槛或放大输出尺寸。

## 2. 先修订的权威契约

- SPEC_01：点击目标与测光自动取消分离；规定上下文失效、会话控制所有权和目标证据。
- SPEC_02：区域资格、真实来源相位、观测反投影、有限校正、独立输出上限及统计域。
- SPEC_06：PHOTO-12/13、CAP-09、DIAG-02 的正负例、配对记录和设备验收要求。

本报告记录结果，不替代以上契约。阈值在规格和配对决策中明确标为实验参数。

## 3. 最终实现

**区域资格：** 使用 64 源像素块，参考加至少两张同曝光候选；候选块支持 ≥70%，
所有参与插值的配准节点具备细节资格。分布式 3×3 探针使用实际逆全局映射加局部
偏移核对二维相位，行列式 ≥0.04。至少四块且占公共裁切 ≥2%，再结合资源准入、
源图 ≤16 MP、2× 公共裁切输出 ≤56 MP，才能选择 scale=2。整图平均和中心相位仅供
诊断；没有降低整图门槛来强制统一像素。

**区域反投影：** 从源图三次插值估计开始，将原始同曝光像素投影到已验证区域，采用
2×2 像素足迹模型及其伴随权重分配残差。每块至少三张、每张至少 256 个可用观测，
搜索 ≤128×128、观测总数 ≤50,000，源图 halo 为 8 像素。最多八次迭代、残差 ±14、
相对初始校正 ±24；初始误差 >1 且模型误差改善 ≥5% 才保留。边界平滑混合，失败/
超限块保留原尺寸多帧估计。每个输出点再次检查局部细节、支持、映射与二维相位。

原尺寸多帧降噪和 HDR 先完成，再放大并进行区域校正。恢复过的高光与原来过曝的
位置通过膨胀保护掩码保留；5×5 亮度范围小于 max(12, 6×块噪声估计) 的平坦像素
不覆盖，以免重建重新引入颗粒。没有任何有效校正像素则退回原尺寸。
贡献/恢复/恢复前 clipping 在原尺寸融合网格统计；重建覆盖在放大网格统计。

JPEG 足迹只是有限近似，不是已知厂商 ISP/RAW 物理模型。模型拟合下降不等于光学
分辨率恢复；没有用锐化、OCR 补字或凭空生成笔画替代观测。

**对焦与控制：** 点击目标持续到新点击或上下文失效；相机重绑、变焦、预览几何或
实际应用的方向变化清除。取景圈和三秒测光取消仍独立存在。快门保留 1500 ms 有界
AF，连拍焦距保持仍依赖实际元数据；记录 tap/centre、坐标、年龄、会话与 AF 支持。
固定焦距/缺失元数据保持未知。开始拍摄时固定控制对象，旧会话不得操作新绑定相机。

**诊断：** JNI 返回 42 项、schema=1 的明确数据包；校验数量、范围、状态和误差关系。
配对 manifest/有界拍摄日志保存来源/裁切、资格面积、实际覆盖、门槛、模型参数、
全部拒绝位与内存计划。流式路径明确原尺寸；资源拒绝与图像证据拒绝分开。
敏感诊断和原始组保留仍仅限测试版，release 不因此收集机型或原始诊断组。

默认 Full HDR、实际镜头切换、简洁圆形倍率界面及设置底部 Banner 保留。
原生高像素仍是独立实验功能；没有实现最大像素专用会话、RAW、Vulkan/GPU 或密集形变。

## 5. 13:25 同组宿主重放

使用原七帧及曝光元数据重放，参考仍为第 1 帧，公共裁切仍为 `(29,29,4038,3014)`。

| 指标 | rc11 结果 |
| --- | --- |
| 输出 | 8076×6028，48.682128 MP，scale=2 |
| 平均整图支持（诊断） | 49.086% |
| 区域资格 | 259/3072 块，占裁切 8.71666% |
| 通过拟合块 | 259 |
| 实际细节校正像素 | 2.01842% 放大输出网格 |
| 模型拟合均方误差 | 37.6906 →20.6336；不是光学真值 |
| 最终拒绝位 | 0 |

同尺度参考/旧合成/新输出检查未见明显新增双重文字，但细节变化有限；不能据此宣称
整屏细字问题已经解决。约 48.68 MP 文件包含大片原尺寸估计的插值，**不是原生
50 MP，也不是全图恢复了同等分辨能力**。

宿主 OpenCV 5.0/解码环境与 Android OpenCV 4.10 不同。手机旧组的恢复计数约
0.4702%，而同宿主旧代码/rc11 分别为 0.00181586% /0.00188159%。曾怀疑这证明
放大丢失高光；补做同宿主旧代码基线后，证据不支持该归因，不能跨环境判断新旧 HDR
改善/退步。原尺寸先恢复加保护是处理顺序约束，真实高光效果仍需同设备配对复测。
恢复前 clipping 也不是最终剩余 clipping。
