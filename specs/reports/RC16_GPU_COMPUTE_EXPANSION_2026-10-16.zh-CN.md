# rc16：继续迁移实际计算到 GPU

2026-10-16；分支 `gpu-hdr`。遵循分析问题 → 分析权威规格 → 修订规格 → 实现与验证。
本轮不扩展 UI、OCR、RAW 或裁切功能，保留 rc15 PPT 未裁切通道保护。

## 证据与实现

此前手机三组 rc14 的 native 约 24–25 秒、局部配准约 11–13 秒；只有三张 GPU 支持图，
GPU 拟合提案为零。GPU 支持图的存在不等于拟合、物理检查和渲染都已卸载。

先修订 SPEC_02 §7.4 与 SPEC_06 GPU-COMPUTE-16，再新增：

- GPU 节点噪声统计：灰度字节一次上传，三个距离的整数直方图选择原上中位数。
  保留边缘 ROI 起点、步长、有效字节排除、样本数及原 double 除数/上限。
- GPU 高光支持图：原九邻居实测区、最近节点、冲突判断、参考裁切掩码及 18 级残差；
  临界点由 CPU 精确复核。同曝光支持图仍用原插值与 14 级残差。
- GPU 原生彩色多帧合成：256×256 输出块，只上传各块需要的原始彩色矩形、门控和节点。
  GPU 完成局部映射、投影、BGR 双线性采样和置信度加权；歧义像素由 CPU 完成。
  原始帧顺序、贡献计数、字节舍入、原生 HDR 基线均保持。

新阶段共用原单一上下文、三个缓冲区、64 MiB 分配上限与共享预算。完成 fence 后才允许
回收旧布局；超时/不确定提交保持隔离。新增启动自检、实际输入 CPU 对照和完整成本校准。
只有 GPU 完整成本不超过 CPU 的 90% 才复用；失败、超预算或不合适的变换回退 CPU。

JNI 性能包扩为版本 2 /54 槽，兼容旧 42/44/50 槽解码。诊断增加实际发布的
`gpuNoiseGrids`、`gpuMergeTiles`、`cpuMergePixels`、`gpuMergeMs`，以及计算版本
`bounded-noise-highlight-color-v1`。GPU 合成时间是总原生耗时的子集，不重复相加。
校准探测的 CPU 回退不会算作 GPU 成片贡献；原生日志另保留探测开销。

全局优化、未获校准的局部 ECC、物理细节验证、HDR 色彩恢复、区域超分迭代、
JPEG 编解码仍包含 CPU 工作。原生高像素流式拍摄保持顺序 CPU 路径。
这是增加实际执行阶段的测试版，尚未完成全部 GPU 迁移或手机性能验收。

## 验证结果

- 实际 Vulkan：普通/高光支持图通过奇数尺寸、非连续行、子像素、缺失节点、冲突及边界
  字节对照；噪声网格覆盖密集/稀疏、未封顶中位数、裁切排除、平坦及小样本。
- 4K×3K 随机/投影彩色合成逐字节与 CPU 相同，贡献计数相同。192 块中约 31% 像素
  由 CPU 完成数值歧义；不能把这些也算作独立 GPU 像素结果。布局切换未超过 64 MiB。
- 加载器、软件设备、管线、分配、绑定、映射、提交和超时八类回退通过；故障后新增核也
  不会继续发布结果。超时夹具保留 7,616 字节隔离资源，没有提前释放。
- CPU 与实际 GPU 完整合成、视差/遮挡/噪声、文档边界、高光与区域重建回归通过。
  debug/release 各 89 项单测，standard Kotlin 和两模式三 ABI 原生编译通过。
- 用户远拍 PPT 冻结样张：普通自动路径实际四次 GPU 噪声网格、五张支持图，彩色合成
  因完整成本选择 CPU。另以宿主专用副本禁用已有 ECC 近似提案、仅强制检验新增合成核：
  192 块、12,326,160 像素，1,168,898 个歧义像素 CPU 完成，逐像素与 CPU 原生合成
  零差异，贡献计数一致。该副本只验证数值，未进入 APK，也不是产品提速测量。
- 以上普通自动重放及专用数值重放最终 BGR 均与 rc15 CPU 基准相同：
  `ec7acef0bda3290b764a330f21e89e874636cef6a5ce2800db0ddbd1d8f03502`。
  包含原生 HDR 和后续重建，未重现白底彩色脉冲；这不是手机 JPEG 哈希验收。

同一冻结样张，预加载、四线程、交错十组 rc15/rc16 自动后端，计入校准/回退/传输：

| 宿主原生指标 | rc15 | rc16 |
| --- | ---: | ---: |
| 首轮 | 9.199 s | 9.789 s |
| 热 p50，后九次 | 8.248 s | 8.057 s |
| 热 p95，后九次 | 8.439 s | 8.339 s |
| 局部配准热 p50 | 2.597 s | 2.330 s |

热总 p50 仅低约 2.30%，首轮更慢，未达到 30% 目标。自动校准具有分支差异：
此次 rc15 接受 30 个已有 GPU ECC 提案，rc16 选择 CPU；合格重建块 142/143。
因此此表不是逐字节等价结果的纯 GPU 加速率，也不能外推手机体验。普通自动合成阶段
在电脑上选 CPU，不应为提高占用率强制改变；手机会独立做成本与精度校准。
