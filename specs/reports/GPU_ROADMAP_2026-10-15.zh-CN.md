# 后续版本 GPU 加速：现状、可行性与迁移计划

日期：2026-10-15（Asia/Taipei）。当前分支 `gpu-hdr`，应用基线 rc12-2016。
本轮交付是后续版本规格与排期；没有启用 GPU、修改应用算法、编译或发送新 APK。

## 结论

可以做，适合保留现有采集、页面与合成架构，逐步替换计算后端。
配准、逐像素融合与有界反投影存在大量并行工作，有值得验证的加速机会。
这属于技术可行性判断；尚无手机上的 GPU 实测收益或画质验收结果。
GPU 也不会自动改善对焦、曝光、原始输入不足或 JPEG 中已损失的文字。

## 问题与代码分析

当前执行链是 CPU OpenCV 与 OpenMP：全局/局部配准、保护性验证、原尺寸
降噪/高光恢复，再执行满足条件的区域重建。原生高像素输入使用另一条有界流式链。

`vulkan_compute_engine.cpp` 参与 CMake 编译，JNI 有头文件引用；全产品源码
搜索没有 `getInstance()` 或 `processHdrLtm()` 的外部调用。只能确认代码未接入，
不能把库里出现 Vulkan 名称当成当前正在 GPU 合成。

旧 `vulkan_hdr_ltm.comp` 是双帧亮度混合与 3×3 LTM/toe，直接按亮度阈值处理。
它没有当前的局部对应、遮挡、可靠短帧、已裁切/恢复保护和区域重建契约；
传入的 `exposureGain` 也未用于 shader 计算。它不应成为新后端的图像算法。
旧封装还逐次创建缓冲/描述符、整图上传读回并等待队列空闲，缺少部分返回值、
形状/步长与无匹配内存类型的检查；新后端需要重做这些边界，而非直接接通。

## 规格分析与调整

现行规格正确标注 CPU 与 Vulkan 未接入，历史 550 ms 等数字已撤回；缺少
下一步 GPU 迁移的资源、同步、画质等价与收益验收契约。

本轮先修订权威 [SPEC_00](../SPEC_00_ARCHITECTURE.md)、
[SPEC_02 §7.1](../SPEC_02_COMPUTATIONAL_PHOTOGRAPHY_AND_VULKAN_HDR.md) 和
[SPEC_06 GPU-01..04](../SPEC_06_IMAGE_QUALITY_AND_ACCEPTANCE.md)，再更新
[待办清单](../../TODO.md)。这份说明不替代权威规格。

后续实施顺序：

1. 补每张照片的阶段耗时与内存，建立 CPU 对照基线。
2. 建有界 Vulkan 计算后端，批量执行灰度、梯度、变形与配准准备/归约，先保留 CPU 判断。
3. 根据热点迁移局部拟合和验证，完整保留现行物理细节、歧义和噪声门控。
4. 让数据连续驻留 GPU，完成降噪、高光恢复与区域重建，减少整图往返和重复分配。

阶段是工作范围，不对应已承诺的四个版本。Upscan 的 LK 候选仍按独立画质门槛
评估；GPU 不成为跳过其接入条件的理由。原生高像素不会为并行而同时解码整组。
采集、AF/AE、队列、JPEG 编解码和磁盘保存单独计时，不默认归入 GPU 收益。

## 验收与实际限制

至少十组同输入 CPU/GPU 配对运行，冷/热启动分开，记录 p50/p95、传输/同步、
峰值内存与连续拍摄的温度趋势，同时验收文字/高光/重影/噪声和故障回退。
暂定处理 p50 降低 ≥30%、p95 不退步为实验工程目标，**尚未测得，不是发布保证**。
完整快门到成片也应有超出测量波动的收益；只报一个 shader 耗时不能宣称加速成功。

不支持、预算不够、GPU 失败或实测不划算时，连接并验收现有 CPU 路径作回退。
发生挂起或设备丢失，需要先安全结束/隔离在途资源；不能直接释放还在用的缓冲，
或带着双套全尺寸分配再开 CPU。无法安全恢复时应显式失败并保留有效原图。

本轮仅核查执行入口、日志时间差、规格一致性与文档链接；GPU-01..04 均未执行。
没有新 GPU 二进制，也未用桌面 Python 的 LK 耗时替代 Android 数据。

## 公开依据

[Android Vulkan 设计指南](https://developer.android.com/ndk/guides/graphics/design-notes)
说明管线复用需要应用负责、存在软件模拟设备，内存类型应按实际能力选取。
手机常共享物理内存，但独立工作缓冲、同步和拷贝仍有成本。
[Khronos 功能启用指南](https://docs.vulkan.org/guide/latest/enabling_features.html)
要求先查询实际功能，再在逻辑设备创建时启用；不能仅凭 API 名称假设可用。
这些支持后端设计原则，不提供 HachiCam 或 Ace3V 的具体速度保证。
