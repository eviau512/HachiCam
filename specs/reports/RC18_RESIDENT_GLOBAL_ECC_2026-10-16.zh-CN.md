# rc18：驻留图像的 GPU 全局 ECC

2026-10-16，`gpu-hdr`。本轮按用户要求，在明确问题后直接继续实现，不再停在分析等回复；
该约定已写入 AGENTS.md。优先原生计算与 GPU，暂不扩展 RAW/OCR/UI。

## 依据与规格

[最新 rc17 手机组](RC17_PPT_DEVICE_2026-10-16.zh-CN.md)完整等待 32.191 s，原生内部
26.950 s；全局配准 7.727 s、局部配准/验证 12.228 s，占原生约 74.05%。46 个 GPU 局部
提案已实际采用，仍未明显降低完整等待。此次直接迁移全局逐像素优化工作。

先修订 SPEC_02 §7.6 /SPEC_06 GPU-GLOBAL-18，明确数学、资源、数值/成本校准、
回退、诊断及验收，再实现。Gaussian/warp/ECC 的公开行为按
[OpenCV 4.10 ECC 实现](https://github.com/opencv/opencv/blob/4.10.0/modules/video/src/ecc.cpp)
核对；使用独立 Vulkan 内核，保留 CPU 原调用作为校准与回退。

## 实现

- 基础曝光的全局 Euclidean（480 初估/1920 精化）及 homography（1280）路径可采用
  GPU。高斯、梯度、变形采样、有效均值/中心矩、Jacobian/Hessian 与投影归约在 GPU。
  图像四个 float 平面和压缩字节在优化期间驻留；每轮只取有限统计量，CPU 解 3×3/8×8
  小矩阵并更新变换。没有每轮下载整图或构造全图 Jacobian。
- 使用原有一个三缓冲区上下文，独立惰性创建七个阶段管线；<=1920 边长、<=280 万
  准备像素、>=16 KiB shared memory。1920×1440 实测总缓冲区分配 50,398,400 字节，
  在 64 MiB 内。不支持的设备仅关闭该阶段，其他已验证核仍可用。
- 保留五抽头反射边界、线性插值网格、最近邻有效性、掩码内均值和掩码外梯度项，
  保留最终更新/返回相关性的语义。仿射采样的行/列定点坐标由 CPU 小数组生成，
  减少 CPU/OpenCV 与 FP32 坐标分箱差异；不传整幅坐标图。
- 数值和成本按模型/准备尺寸分类。冷/热都要与同初值 CPU 的 5×5 分布点一致：
  原始来源坐标 <=0.05 px、相关性 <=0.002；不合格的类不重试。成本保留原 90% 门槛
  及有界重测，包括准备/提交/等待/统计传输/CPU 求解；首次实际开销完整计入照片等待。
- 诊断性能 v4（60 值）新增采用的全局 GPU 调用、迭代数和完整调用时间，嵌套于全局
  配准时间内；旧包兼容。普通/流式入口均重置并绑定本组证据，避免上组计数泄漏。
  release 保持 CPU，未增加敏感信息采集。

## 验证中发现的限制

非零外边界的早期小图透视探针出现 >0.002 相关性差异，不以放宽门槛处理。新增真实
生产校准回归，检查数值拒绝、CPU 输出复用及类隔离。独立已知变换的正例在零外边界内
构造纹理，测试位移/旋转/透视、曝光变化、非恒等初值、非连续行与最大驻留布局。

完整图像回归还发现，短曝光路径中，即使全局变换只有很小差别，也可能改变后续
高光支持判定。因此本轮 **跨曝光 HDR 全局优化仍保留 CPU**，基础帧继续 GPU。
没有通过降低高光/文字资格门槛来消除失败；位移高光恢复和普通/流式回归继续作为门禁。
ORB、相位、候选排序、结构验证、局部物理检查、裁切与区域资格均保持原策略。

实际 GPU 正例、最大布局、CPU 图像回归与完整 HDR/SR 回归通过；通用八类故障隔离及
低 shared-memory 仅局部回退通过。真实生产校准对非零边界探针数值拒绝、原样复用 CPU
结果，随后 12 次调用不重测该数值类，其他计算核仍可用。debug/release 各 **91** 项单测、
standard Kotlin 以及两模式三 ABI 编译通过。

## 最新 PPT 冻结重放

使用同组七张解码后的冻结输入，预加载、四线程，十组交错 rc17/rc18 普通自动后端。
不强制采用 GPU，包含校准、传输、等待和回退：

| 宿主原生指标 | rc17 | rc18 |
| --- | ---: | ---: |
| 首轮 | 10.742 s | 15.200 s |
| 后九次热 p50 | 13.619 s | 11.311 s |
| 后九次热 p95 | 13.834 s | 11.787 s |
| 全局配准热 p50 | 5.261 s | 3.488 s |
| 局部配准/验证热 p50 | 3.766 s | 3.628 s |

本轮热总 p50 下降约 **16.94%**，全局约 **33.71%**；首轮仍更慢。不能将热结果当作
手机/每张照片提速承诺，或将一次冷样本的全部差异归因于某一项初始化。

每轮实际采用 **9 次 GPU 全局优化、28 次迭代**，采用调用的热 p50 合计约 431.775 ms。
这些时间已包含在全局指标中。其他结果：五张 GPU 支持图、四个噪声网格、38 个局部
提案；正式彩色仍 CPU。rc17 同次重放为 37 个局部提案，强筛选的成本路由也不同。

新旧纯 CPU 最新成片逐字节相同：
`16087e735a9a7765e6fc937e588646dd7f15c98ba192f0074ef6d926be6a5bac`。
旧远拍 PPT 的 CPU 基准仍为
`ec7acef0bda3290b764a330f21e89e874636cef6a5ce2800db0ddbd1d8f03502`。

自动后端输出不是字节相同：参考/裁切/8060×6012 尺寸保持；合格重建块 131→112，
实际改动覆盖约 1.0516%→0.8951%。全局近似和后端分支会影响局部证据，阈值没有放宽。
因此总时间不是严格相同输出/工作量的纯内核加速率，全局分段时间应一起看。

原生坐标 `(1550,1050,1150,700)` 的 PPT 区域，同尺寸对照 PSNR 约 43.44 dB，平均绝对
差 0.578 级，绝对差 p99 为 8 级。独立由旧结果建立并腐蚀的白底掩码共 1,041,564 个
输出像素，平均绝对差 0.279 级，未出现本次定义的大幅新增彩色变化
（最大通道差 >32 且色差范围新增 >16）。同倍率目视没有明显新增文字双边或白底蓝斑；
底部细字仍受来源细节限制，不能由 PSNR 宣称变得更清晰或完成画质验收。
高光改动仅相差一个原生像素左右；该屏幕整体高光指标仍不证明卧室灯具已修复。
